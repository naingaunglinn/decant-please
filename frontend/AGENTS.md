# frontend/AGENTS.md — Decant Please! storefront

Scoped rules for the Next.js storefront. Root rules in `../AGENTS.md` still apply.

## Stack

Next.js 16 (App Router, Turbopack) · React 19 · TypeScript 5 · Tailwind v4 ·
GSAP (scroll) · Motion (component state, import from `motion/react`, **not**
`framer-motion`) · Radix Select · Playwright for browser evidence.

`proxy.ts`, not `middleware.ts`.

## Structure

```
src/proxy.ts      ADR-0004: Host → internal /{host}/… rewrite. I/O-free, always.
src/app/          bare shell + unbranded fail-closed not-found
src/app/[host]/   the tenant tree — every public route lives here; the segment
                  IS the validated public host (page.tsx / loading.tsx /
                  error.tsx / not-found.tsx, robots.txt/ + sitemap.xml/ handlers)
src/components/   grouped by surface: catalog, checkout, cart, home, product,
                  tracking, layout, ui
src/lib/          api.ts (fetching, tenant-parameterized), tenant.ts (resolver +
                  tenantPage gate), tenant-context.tsx (useTenant), types.ts
                  (API contract), format.ts, cart-context.tsx
src/hooks/        useCart.ts
scripts/          verify-*.mjs — real-browser regression checks
```

- **The Host is the tenant.** Server pages call `tenantPage(params.host, ownPath)` —
  resolve-or-404 plus the secondary→primary 308 — and pass the slug into `lib/api.ts`
  explicitly; client components read `useTenant()`. Never a build-time shop, never
  module-scope tenant state, never a tenant from a query param or storage. The proxy
  performs no I/O and no authorization — the backend scope is the security boundary.
  The empty `generateStaticParams` exports are load-bearing (they opt routes into
  on-demand ISR); a new static-eligible page under `[host]` should carry one too.
- Catalog fetching happens in **server components**. Cart and checkout interactivity is
  client-side.
- A new surface gets its own directory under `components/`. Do not add to `ui/` unless
  the thing is genuinely a shared primitive.
- `src/lib/types.ts` mirrors the backend's API Resources. It changes only in the same PR
  as the Resource it mirrors.

## Design tokens — fixed, never substituted

Defined as a Tailwind v4 `@theme` block in `src/app/globals.css`. There is no
`tailwind.config.ts` and there must not be one.

| Token | Hex | Use |
|---|---|---|
| `mist` | `#F2F8FC` | page background |
| `ink` | `#212121` | body text |
| `ink-strong` | `#000000` | headlines, numerals |
| `pine` | `#013E37` | buttons, active states, links, prices, icons |
| `pine-soft` | `#E7ECE3` | selected rows, subtle hover |
| `rule` | `#D6E4EB` | hairline borders |
| `surface-alt` | `#E3EEF4` | section backgrounds, image plates |
| `muted` | `#63707A` | captions, secondary labels |
| `status-pending` | `#B08D57` | awaiting confirmation |
| `status-danger` | `#8C4A34` | rejected / cancelled |

Never introduce a raw hex in a component. If a shade is missing, that is a token
decision, not an implementation detail — ask.

**Studio pine ramp (Step 34 PR-3b).** The dark `/studio` admin panel is a deliberate
third register — a "control room", distinct from the mist storefront and the amber shop
panel. Its accent is a `pine-50…950` ramp: pine's own OKLCH hue (182.455°) raised in
lightness and muted to a teal-green (chroma ~0.11), legible on the dark surface at WCAG
AA (400/500 ≈ 9.5:1 / 7.4:1). One ramp, three mirrors — `../design-tokens.json`, the
`@theme` block here, and the backend `StudioPanelProvider` `primary` — changed together.
This is **not** a storefront change: the storefront still uses flat `pine`/`pine-soft`,
and Tailwind v4 emits only referenced shades, so the ramp adds no storefront CSS. Dark is
forced per-panel via a `HEAD_START` hook that never writes the origin-global
`localStorage['theme']` key `/admin` shares, so the Admin panel's theme is untouched.

**The pill motif (rule 2) extends to the admin/Studio panels.** The hairline-bordered pill
— not a filled badge — is the intended treatment for atomic metadata everywhere, Filament
included. The Studio slug chip follows it (the filled-badge default was the exception, now
resolved); this is the admin/Studio answer §3 asked for, not a divergence.

## UI rules

1. **Every control is ≥16px (`text-base`).** Below 16px, iOS Safari zooms the viewport
   on focus. This applies to copied-in library components too — patch them.
2. **The pill is the motif.** Atomic metadata (brand, concentration, size, status) lives
   in a thin hairline-bordered pill, not a generic badge.
3. **One font family.** Hierarchy from weight, tracking, and scale — never a second family.
4. **One motion moment**: the order-status timeline filling like liquid in a vial.
   Everything else stays quiet.
5. **No native `<select>`** remains in the storefront. Use the Radix-backed
   `components/ui/Select.tsx`, styled to the tokens above.
6. Mobile-first. `pine` is used sparingly — never as a large fill except buttons and
   the status track.

## Money in the UI

Format through `lib/format.ts`. Integer Kyat, comma-separated, `Ks` suffix — `50,000 Ks`.
Never a decimal, never a currency symbol.

The cart subtotal is **display only**. The server re-derives the real total at checkout.
Never send a price, a total, or a delivery fee to the API — only `fragrance_id`,
`size_ml`, `quantity`, `delivery_township_id`.

## Acceptance checklist — every UI change

A passing build is not a correct UI. Before reporting done, confirm in a real browser:

- [ ] loading state renders (`loading.tsx` or skeleton)
- [ ] empty state renders
- [ ] error state renders
- [ ] 375px and 1440px both correct
- [ ] keyboard reachable, focus visible
- [ ] form validation messages appear and are readable
- [ ] no console errors
- [ ] every control still ≥16px

## Browser evidence scripts

These are the frontend's equivalent of a test suite. Run the one that matches your
change and paste its real output — not a summary of what you expect it to say.

| Script | Covers | Run against |
|---|---|---|
| `verify-responsive.mjs` | full flow matrix at 375/768/1024/1440, touch targets, 16px inputs, nav/filter/cart/checkout patterns | dev or prod build |
| `verify-home-rails.mjs` | featured vs recently-viewed `<ViewTransition>` name collisions | **dev server only** (needs React dev warnings) |
| `verify-image-fallback.mjs` | missing image falls back to the vial glyph, not a broken icon | dev or prod |
| `verify-print.mjs` | printed receipt is a static document, not the live view | needs `CODE=` + `PHONE=` |
| `verify-tenant-hosts.mjs` | ADR-0004 host routing: per-tenant pages, the step-32 same-path/two-hosts cache case (both orders), fail-closed unknown hosts, secondary→primary 308, per-tenant robots/sitemap | dev proves correctness; **`next start` proves the cache** (fixture snippet in the script header) |

```bash
BASE_URL=http://localhost:3001 node scripts/verify-responsive.mjs
ENGINE=webkit BASE_URL=http://localhost:3001 node scripts/verify-responsive.mjs   # iOS proxy
```

`npm run verify` runs the three that need no fixture arguments.

## Do not touch without saying so first

- the `@theme` block in `globals.css`, or `../design-tokens.json`
- `components/ui/**` and `components/layout/**` (shared primitives — a change here
  touches every surface)
- `lib/types.ts` without the matching backend Resource change
- another surface's component directory while working on yours
